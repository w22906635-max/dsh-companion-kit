# 故障排查

> 按"症状"找，不按"模块"找。

## 她不理我 / QQ 里没反应

按这个顺序查，**从后往前**（越靠后越常见）：

```
1. NapCat 进程在不在？        Get-Process node | Where Path -like '*NapCat*'
2. OneBot 端口通不通？        Test-NetConnection 127.0.0.1 -Port 3000
3. NapCat 登录了吗？          curl -X POST http://127.0.0.1:3000/get_login_info -d '{}'
4. 桥开着吗？目标会话活着吗？  看桥的设置页 / 状态
5. 水位会不会卡住？           ~/.dsh/qq-bridge-watermark.json
```

**最常见的是第 3 步失败**：进程在、端口通，但没登录（返回 `-101`）。

## NapCat 一直出二维码

**症状**：`napcat-out.log` 里每 2 分钟一次 `Login Error, ErrType: 1, ErrCode: 3`，同时不断有新二维码。

**原因**：快速登录票据失效了。

**处理**：
1. 别放着不管——二维码循环本身就在敲 QQ 的门
2. 重启一次（看门狗会等 15 分钟再动手，手动更快）：

```powershell
Get-Process node | Where-Object { $_.Path -like 'D:\NapCat\*' } | Stop-Process -Force
powershell -ExecutionPolicy Bypass -File scripts\napcat\start-napcat.ps1
```

3. 还是不行 → 说明票据彻底失效，**必须人工扫码**。看门狗试满 3 次后会停手并在日志里写明。

## 看门狗不干活

```powershell
Get-ScheduledTask -TaskName 'NapCat-Watchdog' | Select State, @{n='Last';e={$_.LastRunTime}}
Get-Content D:\NapCat\napcat-watchdog.log -Tail 20
```

- 任务 `Disabled` → `Enable-ScheduledTask -TaskName 'NapCat-Watchdog'`
- 日志一行都没有 → 脚本路径错了，检查 `napcat.conf.json` 和 `run-hidden.vbs` 是否存在

## 启动时黑框一闪

用 `run-hidden.vbs` 启动，不要直接跑 `.ps1`：

```powershell
wscript.exe //B //Nologo D:\...\run-hidden.vbs start-napcat.ps1
```

## 脚本报"缺少字符串终止符""Unexpected token"
**PowerShell 5.1 读中文脚本必须 UTF-8 带 BOM。** 没 BOM 会被当 GBK 读，中文把引号撑破。

```powershell
# 补 BOM
$p = 'D:\path\script.ps1'
$t = [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)
[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($true)))
```

检查：`xxd -l 3 script.ps1` 应该是 `ef bb bf`。

## 模型调用返回空

如果某个"短输出"的模型调用（比如让模型挑一句由头）**一直返回空串**：

**`maxTokens` 给太小了。** 带推理的模型会把预算全花在思考上，正文一个字不吐。
实测 `deepseek-flash`：`maxTokens: 120` → 空；`400~800` → 正常。

**不要**因为"输出很短"就把上限压到 100 以下。

## DSH 更新失败（Windows）

**症状**：点「新版本」没反应，安装器日志里是

```
MoveFileExW
Windows error: 5 (拒绝访问)
Source: D:\AI
Destination: D:\AI.old-{...}
```

**原因**：更新器要把整个安装目录改名做备份，但目录里有正在运行的程序。

**处理**：
1. 先确认安装目录里有没有你放进去的**别的东西**（比如 QQ 机器人），有就先搬出去——更新会整个替换目录
2. 完全退出应用（不是关窗口），确认进程列表里没有它
3. 再运行已下载的安装包

**装完如果旧路径消失了**，说明装到了 `D:\AI.new-{GUID}`，可以建个目录联接把老路径接回去：

```powershell
New-Item -ItemType Junction -Path 'D:\AI' -Target 'D:\AI.new-{GUID}'
```

## QQ 桥的补发

补发（离线期间的消息在你回来时补给你）依赖**水位文件**。
如果发现"消息重复补"或"永远不补"，看 `~/.dsh/qq-bridge-watermark.json` 的时间戳，
删掉它会让桥从当前位置重新开始（**不会**重放历史，只是重置锚点）。

## 日志说"要拉起"，但什么都没发生

**执行策略拦的。** 默认 Windows 客户端是 `Restricted`：

```powershell
Get-ExecutionPolicy        # Restricted / Undefined 都算"不给跑"
```

子进程如果没有显式带 `-ExecutionPolicy Bypass`，脚本会被静默拦下——
父进程看到的是"命令执行完了"，但子脚本一行都没跑。

本仓库的 `watchdog.ps1` 已经显式带了这个参数。如果你自己改过，记得保留。

## 计划任务里的路径被"劈成两半"

用 `schtasks /create /tr "...带空格的路径..."` 时，路径会被按空格拆开存进去：

```
Execute   = D:\AIwork
Arguments = space\...\watchdog.cmd
```

**别用 schtasks 传带空格的路径**。用 `Register-ScheduledTask`（本仓库的脚本就是这么做的），
或者把路径放到没有空格的目录下。

验证方法：

```powershell
(Get-ScheduledTask -TaskName 'NapCat-Watchdog').Actions | Select Execute, Arguments
```

## 配置明明写了却不生效

先确认 JSON 合法。最常见的错是**把 Windows 路径写成单个反斜杠**：

```json
{ "NapCatDir": "D:\NapCat" }     ← 不是合法 JSON（\N 不是转义）
```

本仓库的 `_config.ps1` 会自动修正并继续；别的脚本可能直接 `catch {}` 掉，
于是**用默认值跑，你完全看不出来**。改完配置跑一次，看有没有 `读配置失败` 的警告。
